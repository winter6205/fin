## Objective

The 检索档 token rename has two bare letters left. Give them word-form wire tokens by the rule `graph`/`global` established — **the wire token names the MECHANISM, the operator-facing label names the operator's INTENT**: **`A` → `lexical`** and **`D` → `sql`**. The lasting closed set on the **retrieve port** (`filters.search_mode`) becomes **`lexical | graph | global | sql`**; `graph` and `global` are already live and **do not move**. Chinese labels stay exactly **查找 / 知识问答 / 综述 / 真数据库**. The default for a **missing** `search_mode` stays **`graph`** — it does **not** become `lexical`. The four bare letters (`A`/`B`/`C`/`D`) retire everywhere in the same stroke: no entry reads or accepts a letter any more, so a send that still names one is a typed error at the door, not a resolved alias. Ranking stays in **iknow**; the host writes the operator-visible answer from returned `chunks[]`.

**Who:** local operator on the **工作台**; product **知识 MCP** (**iknow-memory**) ranks; fin is host.

**Token map** (retired → lasting → operator label → what that arm actually does):

| retired | lasting | label (unchanged) | what actually runs |
| --- | --- | --- | --- |
| `A` | **`lexical`** | 查找 | iknow lexical/ES hit on an in-window child → cites the PARENT **抽图窗** body (ADR 0060); this increment only retitles that arm, it does not re-rank it |
| `B` | `graph` | 知识问答 | already live; **still the default when `search_mode` is missing** |
| `C` | `global` | 综述 | already live; **Amended by PR #295 / issue #297 (pending merge):** that 档 ships as a product surface on that PR, so once merged it is no longer refused on fin's port as `tier_not_open` — a 综述 send runs the report arm and only a runtime index-not-ready fact refuses it |
| `D` | **`sql`** | 真数据库 | no SQL is wired anywhere; typed `real_db_not_wired` refusal at the host entry and at the arm |

**Source of truth:** **iknow-memory owns the wire enum** — `SEARCH_MODES` in `src/core/retrieval/search-mode.ts` is what the ranking server accepts. **`src/fin/retrieve/tiers.py` is fin's SSOT** — `LASTING_RETRIEVE_TIERS` is the closed set the host produces and the port forwards from, and it is the only vocabulary fin speaks on either wire. The two cannot drift silently because iknow expands first (assumption 6): every token fin sends is one the server has already learned. (The "deliberately WIDER" read-only `TIER_INPUT_TOKENS` once named here is superseded by the 2026-09-22 zero-coexistence ruling — deleted, not widened, so fin accepts no spelling the server refuses.)

Quoted from `docs/CONTEXT.md:240-242` (exact copy of the working copy, which still spells the two surviving 档 with bare letters — the update is proposed in **待写入**, not applied by this file):

- **检索档** (`search mode`): Which retrieve path a knowledge question uses after it has entered **grounded**: A 查找 (lexical-first), **graph** 知识问答 (… MCP `filters.search_mode=graph`, formerly `B`; missing key defaults to graph), **global** 综述 (… MCP `filters.search_mode=global`, formerly `C`), D 真数据库 (real SQL/business DB; document tables stay graph). Assignment reuses the Soft-Track cascade (ADR 0027 / 0062 / 0081) … not a required picker and not silent global. Search-mode copy is call-scoped (ADR 0061).

## Confirmed assumptions (gate)

1. This increment is **wire token change + call-scoped copy strings** on the fin host / **retrieve port** only — the same shape as [`search-mode-graph-global.md`](search-mode-graph-global.md). 档 **assignment** (rules / Jev Choice / inherit / **choice window**) stays [`search-mode-host.md`](search-mode-host.md); the track judge stays [`soft-track-judge-route.md`](soft-track-judge-route.md); the A-arm and SQL-arm behaviour stay [`search-mode-retrieve.md`](search-mode-retrieve.md). No second cascade.
2. The lasting closed set becomes **`lexical | graph | global | sql`**. `graph` and `global` **do not move** — they are already live (fin `fin/retrieve/tiers.py` `LASTING_RETRIEVE_TIERS`, iknow `SEARCH_MODES`, ADR 0081's Choice set). Labels stay 查找 / 知识问答 / 综述 / 真数据库.
3. **A missing `search_mode` still defaults to `graph` (知识问答).** It must **not** become `lexical`: `lexical` is the A-arm path (child lexical hit → parent 抽图窗, ADR 0060), a *different ranking path*, and flipping the default would silently change every omittant caller's `chunks[]`. `fin/retrieve/port.py` `resolve_search_mode(None)` keeps returning `None` (= do not send) and iknow keeps its own `graph` default.
4. **Cancelled by the 2026-09-22 zero-coexistence ruling** — the written spec grew retired-spelling aliases from 2 to 4 and read them at host entries. Shipped instead: the four letters retire in one stroke, so NO entry surface reads `A档` / `D档`, a stored `"A"` / `"D"` audit row, or a `tiers: ["A"]` pin as a 档. Each still reaches `fin.retrieve.tiers` as a plain out-of-set value and is refused there — a typed `invalid_search_mode` at the door and a non-match at every entry seam — with no alias map to resolve it onto a word form.
5. **Cancelled by the 2026-09-22 zero-coexistence ruling** — the written spec kept the `[ABCD]` class in `_TIER_NAMING_RE` so pre-rename utterances stayed readable. Shipped instead: `[ABCD]` never entered the pattern, and the whole pattern is DERIVED from the SSOT (`LASTING_RETRIEVE_TIERS` and `TIER_LABELS` joined longest-first, `re.IGNORECASE` kept), so it recognises exactly the closed set and no letter names a 档. `A档` / `D档` is ordinary prose the judge reads, not a named tier. Future tokens need no shadowing rule: the alternation is built longest-name-first from the tuple, so it cannot drift from the set or be shadowed by a shorter name.
6. **Sequencing, and it is not free to invert:** iknow **expands and retires the letters in one ticket first** (the retire merged into the expand under the 2026-09-22 ruling — it accepts `lexical`/`sql` and drops `A`/`D` in the same change, keeping no alias), then fin retokenizes (fin T1 host SSOT + copy → T2 entry seams → T3 port closed set + live driver; **those ticket numbers are this spec's proposed split — the plan opens via `writing-plans` after ACR**). iknow's expand **blocks** fin T1. If fin retokenizes first, every 查找 and 真数据库 send hits iknow's `parseSearchMode` → `kind:"invalid"` → `GraphragError("INVALID_INPUT")` carrying `invalid_search_mode`, and the A-arm child→parent contract (ADR 0060) never runs.
7. **`sql` names a 档 that is still not wired**: it keeps refusing as **`real_db_not_wired`**. Renaming an unimplemented 档 now costs one table row and one copy string; after a real business-SQL path ships, the same rename would have to move the SQL wiring, its live `-m mcp` driver, its named-failure copy and the operator's muscle memory. **That asymmetry is the argument for doing `D` in this increment rather than a third round.**
8. `lexical` gets **no row** in `TIER_UNAVAILABLE_CODE` — 查找 is open, so an 档未开 refusal must never appear for it. `global` keeps `tier_not_open`, `sql` keeps `real_db_not_wired`. Only `global`/`sql` are routable to a refusal (named_failures `unavailable_tier`). **Amended by PR #295 / issue #297 (pending merge):** on that PR `global` gets no row either — opening 综述 moves it from a plan slot to a real arm, so `TIER_UNAVAILABLE_CODE` becomes exactly `{"sql": real_db_not_wired}` and `sql` is the only 档 routable to a routing-time refusal. A 综述 send then reaches the wire and its refusal is the runtime `community_summary_index_failure`, never 档未开.
9. **Named-failure meanings do not change**, and nothing collapses into empty `chunks[]` as success: 档未开 / 真库未接 / community-summary index failure stay distinct exits. One `retrieve` tool, no host re-rank, no four host retrieve nodes (ADR 0061); ranking stays in iknow.
10. **Cancelled by the 2026-09-22 zero-coexistence ruling** — the written spec widened `TIER_INPUT_TOKENS` (the send door's `tiers` enum, `workspace_http.py`) to lasting tokens + retired letters so a `tiers: ["A"]` send stayed a 200 whose 档 resolved. Shipped instead: `TIER_INPUT_TOKENS` and `TierInputToken` are deleted, the door is typed `tiers: list[RetrieveTier]` over the four word forms, and a `tiers: ["A"]` send is a typed validation error naming the accepted set — the operator sees a refusal, not a silently resolved 档.
11. `LASTING_RETRIEVE_TIERS` keeps **operator-facing order** (查找 / 知识问答 / 综述 / 真数据库), so after the rename the tuple is `("lexical", "graph", "global", "sql")` and `clarify_options()` still renders the window in that order with lasting tokens as option `id`s.
12. Default `uv run pytest -q` stays **Fake** retrieve; Fake is not a 档; the live `-m mcp` driver stays opt-in. **资料类型归档**, community-level filtering from fin, report batching, the citation verifier, the Soft-Track track enum and iknow's own pending graph-mix / report-first tickets are **out**.
13. **Hazard this rename must not create: a per-run 档 is never captured at compile time.** `fin.host.graph._make_locked_graph` keys `_IDEMPOTENCE_CACHE` (`src/fin/host/graph.py:3538`, key built at `:3558-3583`) on graph-identity only — checkpointer / model / jev / classify / caps / summarizer / `memory_port_id` / `enable_choice_window` — and the rule comment above it (`:3532`, block `:3524-3537`) states the design rule: per-call state rides `configurable`, NOT the compiled graph. So no token, alias map, label or copy string may be baked into `compile_graph` as a default: one graph object is reused across every run of the process, and a 档 captured there would leak across threads. The pin already rides the run config (`configurable.pinned_search_mode`, read per call at `graph.py:2491`, stamped at `workspace_http.py:2432`) and the audit is forwarded **verbatim** (`graph.py:527-549`) — both shapes stay exactly as they are; this unit touches only tier CONSTANTS, never a graph argument.

# Spec: corpus-retrieval

> 语料与入库契约。本 spec 只覆盖 **fin** 侧：多格式解析、切分（父子分块 + 场景适配颗粒度）、入库推送、以及支撑这些能力的评测数据集。
> 检索侧（向量 / 关键词 / 图检索、融合、重排、长期记忆存储）不在本 spec 范围内；fin 与本 spec 只规定**调用与数据契约**。
> 与检索服务 spec 的共享部分见「跨仓对齐基线」章节——该章节在两份 spec 中逐字相同，是本 spec 与对方仓对应 spec 之间数字口径与跨仓契约的唯一权威。

## Objective

让 **fin** 成为语料的**唯一解析与切分权威**：任何进入知识库的文档，都由 fin 解析成冻结单元文本、按确定性规则切成父子块、以幂等方式推送给检索服务，并保证推送出去的每一段文本都能被**引用门**在同一冻结单元上逐字符命中。

为什么必须这么做：**引用门**要求答案片段是 fin 冻结单元文本的连续子串。切分若在检索侧按字符硬切，切出的文本就不再是冻结单元的子串，引用门会把真实引用判成凭空生成。因此"谁切分"不是工程口味问题，而是引用门能否成立的前提。

成功形态：**产品语料**与**评测夹具**上的文档，无论 PDF / Word / PPT / Excel / HTML / Markdown / 纯文本，都走同一条 fin 解析—切分—推送链路；同一份字节输入两次解析产出**逐字节相同**的产物；检索侧能力**默认全部启用**，评测集能逐个关掉某一项能力做消融，并给出"百分之多少"的量化提升；两侧报告可合并成一份结论。

### 术语（原文引自 CONTEXT，本 spec 不重新定义）

- **fin**: A **workspace** knowledge-base Agent: the operator asks in a **research thread**; each turn is a **track**; tools and the **citation verifier** bind only to the **research track**. First corpus is operator-held SEC filings; retrieve ranking stays off-graph behind the **retrieve port**.
- **retrieve port**: The only retrieve dependency fin is allowed to have: `query` (+ optional filters) in, ranked chunks with `source_ref` out — MCP-shaped, transport-agnostic.
- **locator**: Cite identity `{document_id, version, unit}`: for the frozen 12, `version` is the PDF sha256 and `unit` is the 1-based pdfplumber `page`; for live EDGAR, `version` hashes the official primary iXBRL `.htm` bytes and `unit` is a deterministic frozen partition of that HTML's stripped text, not an SEC or unofficial-PDF page. The claimed span is a quote string, not a locator field; the citation verifier checks it is a contiguous substring of that unit's frozen text; chunks carry the locator as `source_ref` and are not the identity.
  - Note (fin-side reading, not part of the quoted definition): besides the frozen 12 and live EDGAR, a **local fixture filing** may carry `version` = the sha256 of a local fixture PDF under `data/corpus/pdf/`, with `unit` the same 1-based pdfplumber `page` (in-tree example: `GOOG-2023FY`, `form: 10-K`, one page). This is the frozen-PDF shape pointed at test bytes, not a third locator contract: cite identity, the citation verifier's contiguous-substring check, and `source_ref` not being the identity all hold unchanged. Such fixtures stay outside the §B1 per-format floor — the dataset build counts only `form: 10-Q` rows — so they make no dataset-size claim.
- **citation verifier**: A code gate on the **research track** path to END: a supporting span is a contiguous substring of the answer (v1 minimum 32 characters) that appears in a frozen locator unit this run retrieved or read. Passed spans become the user-visible citations; unknown locators refuse immediately; missing or unmatched spans bounce with a hidden template until the citation-repair cap, then refuse. Non-research tracks skip this gate.
- **ingest**: A CLI that writes frozen locator-unit text from official filings (or the existing extracted tree) into an extracted tree. Retrieve sliding windows are not fin's ranking stack (ADR 0030). The ask path does not fetch EDGAR or open source filings.
- **product corpus**: The operator-selected local extracted tree of official 10-Q and 10-K primary HTML. `fin-serve` retrieve, `read_file`, and the citation verifier read this tree under the live locator contract.
- **eval fixture**: A git-pinned snapshot of **ingest** output, same locator contract as **product corpus**. Default CI contract eval reads only this tree.
- **contract eval**: Default CI harness: scripted model, **eval fixture** only. Required classes: HTML-unit citation pass, unknown locator refuse, catalog miss, cross-period on the fixture. Nine v1 gold cases are not the ceiling.
- **capability eval**: Opt-in or nightly harness on **product corpus** plus a live model; records coverage, abstain, and citation quality. Not a per-commit gate.
- **read_file**: v1 read of a frozen filing by `document_id` and `version`, with 1-based `page` (default 1) and `page_limit` (default 1, cap 3). Misses return `{ error: "unknown_locator" }`; the citation verifier still checks one page per cite.

**语料来源三级（定稿）**

- **一级 · 可引用**：冻结的 10-Q PDF（上游版本已固定）与 EDGAR 官方主 iXBRL HTML。此级产出 locator 与引用证据。
- **二级 · 仅供结构化查数**：XBRL instance XML 与公开数据接口的 XBRL JSON（限流 10 req/s）。供事实表，不产出引用证据。
- **三级 · 派生**：由一级真实内容经确定性导出器生成的 md / docx / xlsx / pptx。内容全部来自真实语料；导出器固定模板与字节序以保证可复现；清单须标 `origin=derived` 与 `derived_from_sha256`；引用身份仍回指原生文档，不新增第二套 locator 契约。
- **禁止**：以数据接口的渲染片段充当 filing 身份；无来源或合成样本计入计数；并发压测访问外部数据源；未达既定门槛即引入额外压力包。
- **许可纪律**：每个引入上游数据的改动都固定上游版本并复核许可与归属。

> 上表各项均为**定稿契约**，不再是建议值。

### B2 部分失败语义（统一）

1. **一臂成功即放行**：一次检索中至少一个臂成功返回（命中或空结果皆可），响应放行。**仅当存在失败或无法尝试的臂时**（无法尝试指按 B3 规则 1 因凭证或地址缺失而未启动）才在信封上置**降级标记**并逐项列出原因；全部臂均成功（无论命中与否）**不**置标记——与 B3 规则 3 及 B2 第 5 条第二类一致。
2. **全部失败即具名失败**：所有臂都失败时返回具名失败（typed error），不返回空结果冒充"命中为空"，也不返回未标记的部分结果。
3. **向量臂失败且主路径无命中**视为全部失败——此时回退能力已失，不构成"一臂成功"。
4. 放行后的降级结果**可用但必须可见**：调用方按 B3 消费，不得因为降级而放宽引用门或静默重试。

5. **无效输入与合法空结果必须区分**（两侧统一，不得混同）：
   - **无效输入**——调用方传入的非法入参（空查询、空内容、空批次等）：返回具名失败（typed error），**不**返回空结果冒充"命中为空"，且**不**按 B3 置 `degraded`（入参非法不是能力失败；误置位即判定失败）。
   - **合法空结果**——入参有效、能力已尝试但未找到任何命中：返回成功响应与空结果列表，不抛异常，且按 B3 规则 3 **不**置 `degraded`。
   - 任一侧把无效输入当作合法空结果处理，或把合法空结果当作失败，均为**契约违反**。

### B3 降级信号：形态与消费

- **形态**：每次检索响应在既有信封上带一个可选字段 `degraded`（布尔）与 `degraded_reasons`（有限枚举列表，每项指明是哪一个能力项、属于"未尝试"还是"尝试失败"）。`degraded` 缺省即未降级。**字段名逐字为 `degraded` 与 `degraded_reasons`，两侧不得另立名称、另作翻译或改用等价表述。**
- **置位规则**（唯一权威定义）：
  1. 默认启用的能力因凭证或地址缺失而**无法尝试** → 置位；
  2. 已尝试的能力调用失败 → 置位；
  3. 能力已尝试但未找到任何命中 → **不**置位；
  4. 调用方显式关闭的能力 → **不**置位。
- **禁止的静默形态**：不得用确定性伪向量、空结果、静默跳过、无标记的顺序回退代替降级信号。任何失败路径必须留下可断言的痕迹——信封标记、具名错误码、可列举的失败记录，三者必居其一。
- **消费规则**：调用方必须读取该标记；为真时不得把该次结果当作完整结果使用，须按 B2 处置、向用户侧暴露可见信号、记录原因。**把降级当空结果处理或忽略该标记，是契约违反。**

## Boundaries

- **Does:**

  1. **多格式解析**：把 PDF / Word / PPT / Excel / HTML / Markdown / 纯文本解析为冻结单元文本 + 结构化元数据；扫描件走 OCR 分支（沿用既有 OCR 写入约定）；解析失败是具名失败，不是空串。
  2. **父子分块**：子块用于精准匹配与引用定位，父块用于给模型完整上下文；命中时返回子块并携带其父块文本；子块文本是父块文本的连续子串，父块文本是冻结单元文本的连续子串。
  3. **场景适配颗粒度**：按（文档类型 × 板块 × 内容密度）查一张**确定性参数表**取分块参数；同一输入两次解析必须产出逐字节相同的产物。
  4. **入库推送**：幂等推送（重复推送不产生重复块、不改变块标识）、结构化元数据、`source_ref` 契约；推送即最终文本，检索侧不再切分（§B4）。
  5. **内容失效**：冻结单元文本变更时对该单元的旧块发起失效，失效请求幂等、可重复执行；失效失败是具名失败。
  6. **检索能力默认全启用**：fin 调用检索服务时不携带任何"关闭某项能力"的开关；能力开关只作为**评测维度**存在，不进入产品调用路径。
  7. **降级信号消费**：fin 读取检索响应的 `degraded` 与 `degraded_reasons`（字段名逐字见 §B3），按 §B2 / §B3 处置，不把降级当空结果。
  8. **语料侧评测支撑**：按 §B1 的数字口径构建评测数据集（多格式、多类型、含困难样本）、按 §B1「消融矩阵」行跑消融配置、出量化报告、跑 §B1 的并发场景，报告可与检索侧报告合并。

- **Confirms with human:** 无 —— 原 F1–F4 已定稿并写回 §B1（并发与延迟、数据集规模与构成、真实语料来源与许可、评测资源预算），本节不再有待人确认项。

- **实现者余地（不是假设，不需要人确认）:**

  - 分块参数表的**具体数值**：契约只约束"由确定性查表决定 + 版本化 + 版本变更触发重建"，数值随参数表版本演进。
  - **各格式冻结单元粒度的具体取值**：方向已定稿（PDF 与 PPT 以物理页、Excel 以工作表内的连续行块、HTML / Markdown 以结构块即标题切分 + 上限合并、纯文本以空行段），取值随解析规则版本演进；契约只约束"同一版本下确定性产出、版本变更即触发重建"。
  - 边界优先级链与内容密度判定阈值的具体取值：契约只约束"整数判定、不使用浮点比较与模型判断"。
  - 单批推送的条数上限：契约只约束"超限分批、不丢尾、可断点续传"。
  - 模块与目录划分、内部字段与类型命名。

- **Out of this spec:**

  - 向量检索、关键词检索、图检索、融合、重排的**算法与实现**（检索服务侧）。
  - 长期记忆**存什么以外**的部分：fin 只决定内容，存储与召回策略归检索服务。
  - 技术栈选型本身（已定档：图数据库主路径 + Postgres 向量扩展 + Elasticsearch + RRF + 重排），本 spec 只承接其**调用契约与数据契约**。
  - 引用门、意图识别、编排、短期/工作记忆的规则改动（本 spec 只保证不破坏它们）。
  - 权限 / 多租户 / 审计合规；Web 检索作为引用证据；视觉模型作为事实来源。
  - 把真实大语料或真实检索服务进程引入默认 `uv run pytest -q`。

## Success Criteria

每条二元可判定：一条命令 exit 0，或一个可断言的性质 / 阈值。数字一律取「跨仓对齐基线」，本 spec 正文不再另设一套。

### A. 默认路径不回归

1. `uv run pytest -q` exits 0；默认套件不读取大语料、不启动检索服务进程、不访问外网。
2. `uv run pytest -q -m eval` exits 0；**contract eval** 的四类必需覆盖（HTML-unit citation pass、unknown locator refuse、catalog miss、cross-period）保持通过。
3. 产品编译路径（非测试）绑定的是 **retrieve port** 的 MCP 适配实现，不是进程内排序实现（ADR 0032）；本 spec 不新增第二个排序栈。
4. **capability eval** 仍是 opt-in / nightly，不是每次提交的门禁。
5. 依赖声明与 lockfile 同步；除解析多格式与表格抽取所必需的库外不新增排序 / 向量 / 图相关的库。

### B. 多格式解析

6. 七种格式（PDF / Word / PPT / Excel / HTML / Markdown / 纯文本）各有 ≥1 个脚本化样本，解析后冻结单元文本非空，且非空单元数 ≥1（每格式一条断言）。
7. 表格类样本（Excel 工作表、HTML 表格、PDF 表区）解析后，单元格文本可被检索命中并可作为 ≥32 字符的 **citation verifier** span 通过校验。
8. 无文本层且含图像的页面走 OCR 分支并写入文本与 `ocr_applied`；OCR 引擎缺失时该单元以具名失败终止，不以空文本记为成功。
9. 加密、损坏、空文件、0 字节、非目标 MIME 的输入，各自返回一个具名失败（不是空串、不是静默跳过、不是异常抛出到调用方）。
10. 解析产物的结构化元数据至少包含：格式、来源字节哈希、**locator** 三元组、单元序号、字符数、语言、解析规则版本、参数表版本；缺任一字段即为解析失败。

### C. 父子分块与确定性（本 spec 的硬约束）

11. 对评测数据集**全量**样本断言：每个子块文本是其父块文本的连续子串；每个父块文本是其冻结单元文本的连续子串。违规数必须为 0。
12. 同一字节输入、同一规则版本 + 参数表版本，连续两次解析 + 切分，产物（含块文本、块标识、顺序、元数据）逐字节相同：全数据集 sha256 比对，不一致样本数 = 0。
13. 分块参数**只**由（文档类型 × 板块 × 内容密度）查表决定；同一三元组两次查表返回同一参数组（golden 参数表快照测试）。
14. **分块必须确定性、可复现**：不得引入任何非确定性来源——同一（字节输入 + 规则版本 + 参数表版本）连续两次切分，产物（含块文本、块标识、顺序、元数据）逐字节相同（与 SC12 共用同一断言入口，本条约束的是"确定性、可复现"这一契约面，不枚举具体手段）。判定：**任何**导致两次运行产物产生差异的来源均属违反，实现手段的选择不构成豁免。断言：全数据集 sha256 不一致样本数 = 0。
15. 检索服务返回的命中块文本，与 fin 推送的块文本逐字节相同（取回比对，不一致数 = 0）——即推送文本即最终文本，检索侧不做二次切分（§B4）。
16. 每个子块在推送载荷中携带其父块文本；父块不单独作为可命中单元参与检索（命中集是子块）。
17. 冻结文本的归一化（空白、Unicode、连字符、软换行）由**一处**规则产生，且冻结单元文本与块文本使用同一规则：跨规则的字符替换导致子串断言失败的次数 = 0。

### D. 入库推送、`source_ref` 与失效

18. 幂等（合并原 SC18 / SC19 / SC38 / SC44，四条合一）：同一批块连续推送的次数取 §B1「幂等基准」行（见 §B1），块总数增量 = 0 且块标识集合不变；并发幂等场景的**并发数与持续时长**取 §B1「并发幂等场景（全写）」行（见 §B1），压测前后块总数增量 = 0；重放同一幂等键返回同一结果、不产生第二份写入；失败推送具名返回且不计入幂等断言。四条全过才算通过。
19. 每个推送块携带 **locator** `{document_id, version, unit}` 的稳定序列化作为 `source_ref`，粒度为冻结单元级；`source_ref` 不是块身份（CONTEXT 原文约束），块标识由 fin 侧确定性哈希生成。
20. 推送的结构化元数据可被检索侧作为过滤条件消费（至少：格式、文档类型、板块、来源哈希、解析规则版本、参数表版本）；缺字段的推送被拒并返回具名失败。
21. 检索服务不可用 / 协议失败时，推送返回具名失败，不静默丢弃、不把写入记为成功、不降级为本地落盘即算完成。
22. 命中映射回 **locator** 失败的块被丢弃（不进入引用证据），检索侧标识永不作为引用证据传给用户；同时该次映射失败**计数**落盘且 >0 时可断言——丢弃不静默。
23. 推送是批量 + 可断点续传的：中断后重推已成功批次不重复写入，未成功批次被重推后补齐（补齐后块数 = 预期总数）。
24. 内容失效：冻结单元文本变更（新 `version`，或解析规则版本 / 参数表版本变更导致块文本变化）时，fin 对该单元旧块发起失效；失效后以任意查询时刻检索，该旧块出现次数 = 0；重复发起同一失效请求结果一致（幂等）；失效请求失败时具名返回，不静默。

### E. 检索能力默认全启用

25. fin 的产品调用路径不携带任何关闭检索能力的参数。**「能力关闭类键」的判定规则（可判定，静态检查据此判 0）**：
    - **K1 键名清单**：fin 侧维护一份**能力开关键名快照**，逐项对应 §B4 列出的 8 个能力项；快照条目数必须恰为 8（多、缺、为空即本条失败——不接受空清单蒙混）。键名取检索服务侧能力开关的枚举名（命名权归检索服务），检索侧枚举名变更时该快照必须同步更新，否则本条失败。
    - **K2 匹配规则**：产品调用的参数集合中，任一参数键名命中下列任一形式即计入"能力关闭类键"（`<X>` 表示 K1 快照中的任一键名）：① 前缀形式——键名匹配 `^(disable|no|off|without|exclude)_<X>$`；② 后缀形式——键名匹配 `^<X>_(enabled|disabled|off|on)$` 且取值为假值；③ 键名直接等于 `<X>` 且取值为假值。
    - **断言**：对产品调用路径做一次静态检查，命中 K2 的参数键数 = 0；且快照文件存在、条目数 = 8、非空。两条全过才算通过。
26. 能力开关只出现在评测调用路径：同一份评测集，产品路径与"全开"评测配置的检索结果集相同（顺序与分数可不同，命中 **locator** 集合相同）。

### F. 评测数据集

27. 数据集清单存在且可校验：**覆盖的格式种数、每种格式的样本数下限、样本总数下限**均取 §B1「数据集规模」行（见 §B1，本 spec 不另设一套）；样本须为**真实**样本（非合成、非占位文本）；每个样本带来源与许可记录，缺来源或标记为合成的样本不计入计数。
28. 每种格式至少 1 个困难样本（扫描 PDF / 多栏排版 / 合并单元格 / 图文混排 / 内嵌公式 / 页眉页脚干扰之一），困难样本解析后冻结文本非空。
29. 数据集覆盖 ≥3 种文档类型（至少：财报叙述、表格密集、条款列表），每种类型具备 ≥1 条人工标注的"应有命中"标注（问题 → 期待 **locator** 单元）。
30. 数据集可一键重建：重建后的样本清单哈希与清单文件记录一致（重跑不一致样本数 = 0）。

### G. 消融实验与量化报告

31. 消融矩阵：配置的**总数、构成（全开 + 逐项关闭 + 全关）**均取 §B1「消融矩阵」行（见 §B1），关闭项即 §B4 的 8 个能力项；一条命令跑完全部配置并落盘结果，缺失配置数 = 0。
32. 每个配置输出 §B1「指标集」行列出的**全部字段**（字段清单以 §B1 为唯一权威，本 spec 不另设一套），并输出相对"全关"基线的**百分比提升**（数字，不是"更好"）；任一指标缺失的配置数 = 0。
33. 每个配置的**重复次数下限**取 §B1「消融矩阵」行（见 §B1），报告中写入逐次原始值 + 中位数；重复次数未达下限的配置数 = 0。
34. 报告同时给出全开相对"仅关掉某一项"的差值（即该项能力的贡献度），缺失项数 = 0。
35. 报告中任一"提升"结论必须同时给出样本数与基线的绝对数值；只给百分比不给绝对值视为该条不通过。

### H. 并发评测

36. 并发 L1 场景（检索 / 读取路径，不含 LLM）：**并发数、持续时长、读写比、总请求数下限、错误数判定、延迟阈值**均取 §B1「并发 L1（检索 / 读取路径，不含 LLM）」行与「延迟阈值」行（见 §B1）；p95 与 p99 落盘且不超阈值，压测前后块总数不变。并发 L2 场景（完整 run，含 LLM）：**并发数、持续时长**与其自身的 **p50 / p95 判据**取 §B1「并发 L2（完整 run，含 LLM）」行（见 §B1），错误数 = 0；L2 不套用「延迟阈值」行的 p95 / p99 门槛。
37. 并发幂等场景：**并发数与持续时长**取 §B1「并发幂等场景（全写）」行（见 §B1），全写；错误数 = 0，压测后块总数 = 压测前块总数（幂等不被并发破坏）。
38. 其他维度各有一条命令可跑并落盘：**引用门**通过率、拒答率（应拒答而拒答 / 应拒答而未拒答）、首命中位置分布、重复提交幂等；缺维度数 = 0。**长文档召回与跨文档多跳召回不属于 fin 的评测维度**——二者是检索服务侧能力，其数字由检索服务侧 spec 产出，fin 侧报告在合并时**只消费、不重算、不重复建模**。断言：fin 侧评测维度清单中出现这两项的条数 = 0。

### I. 降级信号消费与静默失败

39. 降级消费：fin 的检索调用必须读取响应信封上的 `degraded` 与 `degraded_reasons`（字段名逐字见 §B3，不得另立名称或改用等价表述）；`degraded` 为 true 时按 §B2 处置——有结果则记录 `degraded_reasons` 的每一项并向用户侧暴露可见信号、请求失败则转为具名失败，**不得把降级当合法空结果处理**；降级不得放宽引用门的任何判定。断言：注入降级响应（信封 `degraded` 为 true）后，fin 侧既未记录原因也未暴露信号的次数 = 0。
40. 静默失败清零：本 spec 涉及的失败路径（解析失败、OCR 不可用、推送不可用、协议失败、映射失败、失效失败、后台路径失败）在失败清单中逐条具名，且各自留下可断言的痕迹（具名错误码 / 计数 / 可列举记录）；清单中出现"无痕迹的失败路径"条数 = 0。
41. 跨仓基线一致：本 spec 与检索服务 spec 的「跨仓对齐基线」章节正文逐字节相同——按 §B6 的方式取两段正文分别计算 sha256，两值相等则通过，不等则失败。

### J. 边界五类测试（沿用仓库既有约定）

42. empty：按 §B2 第 5 条区分。空文档、空查询、空块批次推送属**无效输入** → 具名失败（typed error），不返回空结果冒充"命中为空"，且不置 `degraded`；入参有效而未命中属**合法空结果** → 成功响应与空结果列表，不抛异常、不置 `degraded`。断言：注入无效输入后未返回 typed error 或未计入"输入校验失败"计数的次数 = 0；注入有效但未命中的查询后被当作失败或被置 `degraded` 的次数 = 0。
43. negative：按 §B2 第 5 条二分。**冲突**过滤条件（互斥条件同时指定）属无效输入 → 具名失败，不返回空结果；**未知**过滤条件（语法合法但无匹配）属合法空结果 → 空命中、不抛异常、不置 `degraded`；未知 **locator** → `unknown_locator`；命中映射失败 → 该命中被丢弃、计数 +1、不进入引用证据。断言：注入冲突过滤条件后未返回具名失败的次数 = 0；注入未知过滤条件后被置 `degraded` 的次数 = 0。
44. overflow：单文档块数超限 → 分批而非截断丢尾；单次推送批量超限 → 具名溢出；**read_file** 页上限沿用既有上限不被本 spec 放宽。
45. concurrent：同一进程内两个重叠检索调用各自返回合法结果或具名失败、不抛异常；同一批块并发推送幂等（并入 SC18）。
46. exception：解析失败、OCR 不可用、推送不可用、协议失败、映射失败、失效失败——各自具名，不出现空 `except` 吞掉失败，不出现"失败即空成功"。

## 假设清单

**假设清单已清空，B1 全部为定稿契约。**

原 F1–F4 已完成调研并定稿，取值写回 §B1 对应行，本 spec 不再有待确认假设：

- **F1 — 并发与延迟阈值**：拆为两层 —— L1（检索 / 读取路径，不含 LLM）并发 16 / 120 秒 / 读写比 9:1 / 总请求数 ≥ 1200，配 p95 ≤ 800 ms、p99 ≤ 2000 ms；L2（完整 run，含 LLM）并发 8 / 120 秒，用其自身的 p50 < 60 s、p95 ≤ 120 s 判据。
- **F2 — 数据集规模与构成**：源文档 ≥ 140 篇（≥ 7 种格式 × 每格式 ≥ 20 篇）、切分后块 ≥ 20000 且 ≤ 120000、查询 ≥ 100；查询分 CI 契约集与全量集两档，四类查询各 ≥ 10%。
- **F3 — 真实语料来源与许可**：语料来源分三级（可引用 / 仅供结构化查数 / 派生），派生格式由一级真实内容经确定性导出器生成；缺来源或合成样本不计入计数。
- **F4 — 评测资源占用**：消融 30 次合计约 3–8 小时走夜间窗口串行，全量 100 题每周一次约 1–2 小时，两个并发场景合计 ≤ 30 分钟（含预热）；压测机与服务分离、语料全本地。

## Inherits / Changes

**Inherits:** Python 3.12 + uv + pytest；**retrieve port**（`query` + 可选过滤进，带 `source_ref` 的排序块出，MCP 形态、传输无关）；默认 pytest 用 Fake 端口、opt-in 才连真实检索服务（ADR 0032）；**locator** `{document_id, version, unit}` 与 `source_ref` 非身份的约束；**citation verifier** 的 ≥32 字符连续子串门槛与未知 locator 立即拒答（ADR 0021）；**ingest** 是 CLI、抽取产物是查询 SSOT、提问路径不抓取（ADR 0020）；**product corpus** / **eval fixture** 两层树与同管线约束（ADR 0029）；官方 HTML 为活跃引用单元（ADR 0028）；附加过滤与 XBRL 事实工具的键名不重命名（ADR 0031）；一个编译图（ADR 0013）；**contract eval** / **capability eval** 两层评测（ADR 0029）；Postgres 为权威源、Redis 可选（ADR 0036）。前序 spec：`specs/s1-corpus-retrieve.md`、`specs/enterprise-kb-agent.md`。

**Changes this spec adds:**

1. **多格式解析归 fin**：PDF / Word / PPT / Excel / HTML / Markdown / 纯文本统一由 fin 解析成冻结单元文本 + 结构化元数据；扫描件走 OCR 分支并写 `ocr_applied`。
2. **切分与父子分块归 fin**（**改判**，见下「冲突声明」）。
3. **场景适配颗粒度表**：（文档类型 × 板块 × 内容密度）→ 分块参数的确定性查表；规则版本 + 参数表版本进元数据；版本变更就地全量重建。
4. **引用门兼容硬约束**：块文本必须是冻结单元文本的连续子串（父子两级都是）；冻结文本归一化规则单一权威，块与单元共用。
5. **入库推送契约**：幂等键（§B4）+ 块标识（确定性哈希）+ 批量分批 + 可断点续传；推送失败具名，不静默、不降级。
6. **内容失效契约**：fin 在冻结单元文本变更时主动发起旧块失效；失效请求幂等，失败具名。此前该能力只在检索侧被标注为"对 fin 的阻断项"，本 spec 补上 fin 侧的触发义务。
7. **降级信号消费契约**：fin 读取响应信封上的 `degraded` 与 `degraded_reasons`（字段名逐字见 §B3），按 §B2 / §B3 处置，不把降级当空结果；此前 fin 侧只认结果列表、不读降级标记，故障链被完整保留。
8. **检索能力默认全启用**：产品调用不携带能力关闭参数；能力开关仅作为评测维度存在。
9. **语料侧评测支撑**：按 §B1 的数字口径建数据集、按 §B1「消融矩阵」行跑消融配置、出量化报告（绝对值 + 百分比）、跑 §B1 的并发场景；报告与检索侧报告可合并。
10. **技术栈定档 B 的 fin 侧承接**：图数据库主路径（找实体 → 图多跳主检索 → 图上未找到时回退向量 + 精度层）；向量为单一能力在两个环节被调用；精度层在「找实体」与「回退」两处都在场，与向量互补、不做主备切换；Postgres 向量扩展原地加索引、不搬迁；Postgres 为权威源，检索索引是派生的、可重建的——fin 侧据此承担"可重建"义务：任意时点都能用同一规则版本与参数表版本从权威源重建全部推送内容。
    - **排除论证（为什么精度层不落在 Postgres 侧）**：共同约束四条——① 索引期与查询期必须共用同一分析器，否则词元不一致导致召回不稳定；② 定档 B 要求中文分词、Okapi BM25、短语查询、字段加权四项作用于同一份词元流，拆到两个引擎会出现"分了词但排序看不见"的割裂；③ 权威源只保持"权威数据 + 一个向量扩展"的最小职责，实例级扩展会把词法能力与数据库版本、镜像、升级路径绑定；④ 派生索引只有一个重灌入口，不允许第二套词法栈。
      在此之上**逐项排除三条 Postgres 侧方案**（完整论证由检索服务 spec 的「新依赖的排除论证」承载，本 spec 不复制第二份）：

      - **只换 Postgres 文本配置（不引入新依赖）**：配置只做词元过滤与归一化，**不产生切分能力**；连续中文仍整体成为一个词元，中文词法臂召回趋近于零的问题不被解决——能力上就不成立，不是成本问题。
      - **Postgres 侧中文分词扩展（zhparser / pg_jieba / pgroonga 一类）**：切分能力上可行，但与共同约束 ② 冲突（四项能力需要**一处排序权威**，留在权威源侧即出现第二套排序口径），并与 ③④ 冲突（实例级安装绑定、词典升级触发权威侧数据变更）。
      - **N-gram 轻量方案（pg_bigm 一类）**：安装轻、无需词典，但二元组切分不做词义切分，噪声词元数量级放大，精确串型与实体锚定型查询精度下降，与"精确串参与排序""图找实体"两处目标方向相反；Okapi BM25 的 tf 语义被破坏（词频统计对象从词变成片段，k1 / b 调参不再对应词级行为）；短语查询与字段加权仍需另一套实现；索引体积与写入放大落在权威源侧；且仍是实例级扩展，未解除 ③④。
      - **结论**：四项合为一个精度层，由 Elasticsearch 承担；Postgres 侧不再保留第二套词法排序实现。

# Plan: Domain-neutral routing and versioned enterprise evidence contracts

**Goal:** Make fin answer enterprise-material questions through source-specific, versioned evidence contracts and enforce those contracts at each fin consumer boundary.

**Approach:** Session E owns fin's domain-neutral routing and evidence-schema consumer. Keep the tracked change focused on Q1 and its final integrated browser acceptance, and add Session E as a native the tracked change blocker. Inside Session E, route, runtime validation, persistence, transport, and web changes remain separately reviewable logical changes. One issue represents this execution session; tracer bullets are ordered work inside it, not new issues.

**Operator-approved product decisions:** fin answers questions and extracts requested fields from authorized enterprise materials. Such requests enter the knowledge-QA path; absent evidence, insufficient permission, or an unavailable capability yields a named refusal rather than `off_topic` or a plausible answer. XBRL and financial numeric gates remain available for financial tasks with a matching source; an amount by itself does not select them. The first non-financial behavior slice uses an expense-policy document, with a grounded answer for present rules and explicit insufficient-evidence behavior for absent rules. Reuse iknow-memory's existing entity/relationship model; field extraction is in product scope, but this plan does not implement a credit-specific extractor, underwriting score, or approval workflow.

### Contract matrix to freeze in E1

Every serialized contract explicitly versions its shape and distinguishes its source/record kind. Freeze the exact shared `source_kind` (or equivalent) vocabulary, versioning policy, canonical schema representation, producer/consumer fixture handoff, and legacy behavior before coding. The common envelope contains only fields genuinely shared by all source types; each type keeps its own payload, locator rules, bounds, and semantic verifier.

| Contract profile | Behavior that must be preserved and validated |
| --- | --- |
| Document citation | Bind the claim to the existing document locator identity (`document_id`, content version, and unit) and an exact quoted span. Confirm the locator resolves to the cited version/unit and the quote occurs there. Keep current citation-verifier text-span rules scoped to document-text citations. |
| Attachment / visual observation | Keep visual claims in their own typed lane. Bind them to the attachment/content version and observed page or region/crop identity; validate bounded coordinates and content/crop hashes where present; confirm the observation belongs to that attachment version and run. Visual observations are not document-text citations and cannot be moved into the citation array. |
| Financial-fact validation profile (not a citation kind) | Bind each XBRL fact to the filing/document and exact source version, plus concept, context/dimensions, period, numeric value, and unit. Validate against the source fact row and existing financial numeric gate. When a page-based presentation exists, validate its presentation locator/value/unit against that page; for HTML filings, use the actual deterministic source unit and never invent a page number. Keep this profile restricted to financially relevant tasks with a matching source. |
| Database row snapshot | Preserve the that pull request proposal's source, record key, query time, structured fields, and summary, plus a stable identity/digest for the stored result snapshot as settled by E1. Reading a citation reuses the stored snapshot and timestamp; explicit refresh creates new evidence without replacing the prior answer. Re-check current authorization when reading historical evidence. Never encode a row as a document chunk or make it pass the text citation gate. A well-formed identity/context does not prove a caller is trusted or authorized. Decide the distinct valid zero-row result and its behavior with the tracked change. |
| Business field observation | Define a bounded extension for requested fields tied to an existing business subject/record and source locator/version. Preserve the original extracted value, any typed/normalized value, and status such as missing, ambiguous, conflicting, or unverified so conflicting sources remain visible. Reuse the existing iknow entity/relationship model; do not create a graph node per field. Define task-specific field sets only when a real use case is selected. |

For all profiles, E1 decides required/optional fields, unknown-field and unknown-version behavior, strict timestamp/hash parsing, source and payload/count bounds, and the compatibility policy for saved turns created before versioning. No silent coercion, invented defaults, empty-result substitution, kind coercion, or dropped fields. Shape validation, source-specific semantic verification, and identity/authorization are separate checks. Preserve distinct typed outcomes for malformed input, unsupported contract, missing data, permission denial, capability unavailable, and infrastructure failure.

**Input-class matrix:** Each public boundary records which of the following classes apply and the expected typed result. Empty is not conflated with malformed or with a missing source; negative covers wrong/missing types, versions, hashes, timestamps, locators, units, and trust; overflow covers payload, row, field, or event bounds chosen in E1; concurrent applies to stateful refresh, persistence, thread, and stream operations rather than a pure decoder; exception covers producer/network/database/persistence/serialization failures. Every applicable class gets a contract test at its owning boundary. The the tracked change producer owns its SQL request/execute classes; Session E owns fin's MCP ingress, persisted replay, HTTP/SSE, and web runtime decoders. No failure class may collapse into an empty success or an undocumented default.

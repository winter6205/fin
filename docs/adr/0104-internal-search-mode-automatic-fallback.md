# 0104. Retrieval mode is internal and unresolved selection falls back to graph

Date: 2026-10-20
Status: accepted

The operator adopted automatic internal retrieval selection after the [QA closeout](../verification/2026-10-20-qa-final-closeout.md) showed an answerable annual-leave question paused at a mode picker: Jev chose lexical at 0.44 and recorded `mode_jev_exit=low_confidence`; a manual choice was required before the cited answer appeared. Keep rules/debug pins, eligible same-job inheritance, and the closed-set Jev judge; when these leave a grounded turn unassigned, use `graph` with `decision_tier="fallback"`, conservative policy confidence 0.0, and all original available judge signals. The host owns routing behind the question-to-answer interface, and content ambiguity that changes the answer is the reason to ask a person to clarify; routing uncertainty is explained by its receipt.

This partially supersedes the unresolved-mode window/terminal-failure clauses of [ADR 0062](0062-search-mode-soft-track-cascade.md) and [ADR 0081](0081-search-mode-gray-zone-jev-choice.md). It preserves the Jev closed set and confidence floor, debug `tiers`, inheritance, named failures for explicit unavailable selections or failed retrieval, call-scoped usage, and the existing single graph. Keep `enable_choice_window` enabled for Fast proposals; under the 2026-10-20 clarification amendment below, genuine content clarification is a terminal question rather than a choice window. Both ordinary and developer UI omit internal mode names; developer diagnostics can present provenance, confidence, and EXITs, while raw mode tokens remain in machine receipts/logs.

**Trade-off:** graph may be less specialized than a confident lookup or synthesis choice, but an answerable question can proceed without requiring the person to understand internal routing. Retain original `mode_jev_label`, `mode_jev_confidence`, `mode_jev_exit`, and error type when available; fallback confidence is not a fabricated Jev probability. Failures after selection still propagate, with no alternate-mode retry or invented evidence.

**Alternatives considered:** continue presenting a mode picker on judge uncertainty; disable all choice windows; lower the confidence floor; characterize every corpus as financial filings. The observed failure calls for hiding routing responsibility within the host rather than changing the judge threshold or removing Fast/content confirmation.

**Architectural cost:** this changes a cross-module receipt and interaction contract previously established by two ADRs. Reversing it would require reintroducing user-visible routing responsibilities and updating host/web/test consumers together; the distinction between content and routing clarification is otherwise surprising from the old interrupt implementation. This is a durable responsibility choice with a real specialization-versus-interruption trade-off.

**Clarification continuation (2026-10-20 amendment):** content clarification is a terminal question plus a new-message continuation, not an interactive pause/resume. The host retrieves first; when exactly one candidate document can answer — only one catalog document covers the question, for example — it answers directly and states that document, and only multiple real candidates whose choice would change the answer justify a clarification. The question is opened after retrieval as the turn's terminal outcome. Its options are the catalog's own documents: the document title, or its `document_id` when the catalog records no title, taken from the catalog or that turn's retrieval hits. The option set deliberately does not read the `company` / `period` fields: these are optional descriptive metadata, while new public document identity derives from trusted corpus scope and raw file bytes. A clarification option therefore remains valid when those metadata values change. The model may phrase the question but must not invent an option, and neither the prompt nor an option names an internal slot such as `company` or `period`. When no real option exists, the question still accepts a free-text answer: `other` with non-blank `free_text`. A reply arrives on the normal send door with `question_id` and opens a new turn in the same thread, with the unchanged task goal and the thread transcript carrying the original question as context. The host writes the turn's real `task_id` on that pending question and never publishes a task clarification with an empty one, which the web keeps rejecting; a send that carries an unknown `question_id` and no answer value is a normal follow-up message, never a silently dropped input, while an answer attempt naming an unknown or superseded question keeps the existing typed stale-reply refusal.

**Document-choice exception:** the existing document-choice interrupt is unchanged and remains the one interactive resumable mechanism, for that specific document ambiguity. Its committed question pauses the graph, and an accepted pick or `other` reply continues the same paused run and receipt through the existing resume path (`Command(resume=...)`, the machinery `POST /resume` exposes); reload reads the committed question without a bodyless resume. Its admitted candidate set, deterministic labels, four-choice bound and Other label stay as the shared wire contract defines them. The terminal continuation above must not be applied to it. Interactive resumable pauses for content clarification belong to the Runtime architecture and are not implemented on this branch.

**Delivery status:** design accepted and implemented on `fix/qa-design-correction-20261020`; the [implementation report](../verification/2026-10-20-qa-design-correction-implementation.md) is still recording the evidence for this branch, including the clarification continuation. The fresh runtime acceptance remains incomplete and this ADR does not claim that all checks pass. Receipt scope is the existing current-turn graph state, invoke result, and terminal SSE/status payload. Historical RunRecord/TurnRow reads omit search-mode decisions; this ADR does not add a persistence format or claim history/reload durability. The [host spec](../../specs/search-mode-host.md#clarification-contract) owns the detailed contract and the [demo amendment](../../specs/demo-seed.md#adopted-qa-design-correction-2026-10-20) owns thread entry/home navigation. The old QA result remains failed automatic-Q1 evidence until independently superseded by a new runtime report.

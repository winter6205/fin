# 0027. Soft-Track turn orchestration (multi-track host graph)

Date: 2026-08-24
Status: accepted

fin is a normal conversational agent on one host graph; **grounded** (ADR 0061; formerly the `research` track enum) is the specialization that binds tools and runs the citation verifier. Each turn is classified in-graph (rules primary, **Jev** Choice only when ambiguous — ADR 0080) into `dialogue` / `clarify` / `off_topic` / `grounded`. Non-grounded tracks do not bind tools, do not enter the citation gate, and may `done` with empty citations. Off-topic is a soft model reply under system bounds, not `refuse`. Classification uses rules first and optional closed-set Jev hints; a missing, failed, malformed or unusable hint falls back to authorized retrieval. Actionable missing user conditions may still clarify. Product route intent (`retrieve`, `overview`, `chat`, `policy_refuse`) is separate from Track and final semantic outcome: retrieval/overview use grounded; chat uses dialogue/off_topic; an explicit existing policy refusal is a disposition, never a fifth track. Document ambiguity is decided after retrieval inside grounded, using Runtime's single pending question and same-run continuation.

**Phase topology (not final):** Soft-Track v1 ships a **flat** `StateGraph` with conditional edges so routing lands first. This is **not** a permanent ban on subgraphs. Treat orchestration (route / clarify / dialogue / off_topic) and research execution (model–tools–gate) as separate logical boundaries even while flat. Upgrade triggers that **require** reopening topology (do not keep piling into flat): research path ≈8+ nodes or a multi-stage verifier pipeline; parallel fan-out (`Send` / map-reduce); research needing separate compile/test; Soft-Track stable and the next capability is XBRL / numeric / peer compare. Later agents must not cite “D14 chose flat” to refuse a subgraph.

**Memory:** Full message / turn / citation history stays durable. Minimal research context is an **append-only status-snapshot history** in `AgentState` (checkpoint SSOT; not `thread_store`); the latest snapshot is the active view for routing; older snapshots remain for audit/backtrack. Company change appends a new snapshot with finance-dependent fields cleared while carrying forward accepted versioned source intent. A new unscoped question or mode change also preserves it; only explicit user replacement/clear accepted by Runtime changes it. Source Scope rechecks current authority and proposes changes; Runtime alone writes them into the existing checkpoint.

**Prompts / UI / ops:** Per-track call-scoped system prompts (not checkpointed). Optional light UI hint on research only—no Chat|Research mode picker. Soft-Track ship gate: five scripted contract suites (greeting / clarify / off_topic / true 10-Q / inherit follow-up), boundary-tested, opt-in mark (not every default pytest). Persist `track_decision` on each `RunRecord`.

Amended 2026-09-21 (ADR 0080): the clause “Ambiguous classify reuses `FIN_MODEL` until cost/latency evidence says otherwise” is replaced. Product gray-zone classify is a **Jev** Choice over the four **track** leaves; default pytest stays Fake.

**Rejected for this increment:** HTTP-only router; gate-predicate-as-router; single default fallback track; Chat|Research chrome; supervisor handoff; training a separate intent model; dual-writing slots into `thread_store`.

Amended 2026-10-16: the operator adopted optional-Jev retrieval fallback, separate route intent and versioned sticky source intent after fresh architecture review. This supersedes the old judge-down-to-clarify behavior together with ADR 0080; the four tracks, durable history and task authority remain. The trade-off is possible extra retrieval work and explicit input/scope coordination instead of an unavailable judge forcing clarification. Exact mapping and reply/scope encoding are frozen in the [grounded contract](../../specs/qa-chain-grounded-experience.md) and [shared contract](../../specs/question-task-runtime-contract.md). Design adoption does not claim implementation.

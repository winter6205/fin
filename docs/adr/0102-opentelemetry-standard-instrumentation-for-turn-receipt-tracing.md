# 0102. Standard OpenTelemetry instrumentation replaces the hand-rolled OTLP exporter
Date: 2026-10-19
Status: accepted

The adopted T12 design exported turn receipts over a hand-written OTLP/HTTP JSON encoder using only the Python standard library, addressed directly at one Langfuse ingestion endpoint with a vendor-specific header. That design bound the transport to a single vendor, hand-maintained an envelope that already had a standard equivalent, and simultaneously forbade the plan from instrumenting the execution seams it was meant to observe: a per-turn trace is not a receipt projection alone, so every interesting seam — routing, retrieval, model invocation, citation verification, admission — had to be either left untraced or approximated by inferring it from receipt counters.

Use the OpenTelemetry Python API, SDK and OTLP/HTTP exporter, and hand-write exactly five spans over the existing execution seams: **classify_node**, **retrieve_tool**, **model_node**, **citation_gate_node** and **admit_decision**. No automatic instrumentation, no general callback handler, no second tracing abstraction. Select the exporter through the standard `OTEL_*` environment variables. No exporter is selected by default; the supported non-default choices are **pg**, **console** and **otlp**, and all three stay off unless explicitly selected. **pg** writes spans to fin's local PostgreSQL sink and additionally requires the fin-specific `FIN_TRACE_SPAN_DSN`; startup refuses **pg** without it rather than failing later in the export worker. **console** writes spans to the process output, and **otlp** exports them to any OTLP/HTTP endpoint named by the standard `OTEL_*` variables. Write no vendor-specific exporter code: Langfuse is reached as an OTLP/HTTP endpoint by configuration alone, the PostgreSQL sink is fin's own store, and any other OTLP-compatible backend is equally unremarkable.

Correlate deterministically instead of trusting ambient context. The trace id derives from (**thread_id**, **turn_id**), so a turn's receipts and all of its execution spans land in one trace with no parent gap. Each execution segment is a root span whose own id derives from (**thread_id**, **turn_id**, **segment_seq**); the receipt projection span sits as a sibling at the same level, never as an orphan. **segment_seq** becomes a durable receipt column defaulting to 0 and advances in the same transaction as the accepted reply that resumes a clarification, never in any other write within the segment, and never as a substitute for `revision` or an in-process counter. Retrieval runs in a worker thread, so the trace context is passed into `mcp_adapter`'s `asyncio.run` explicitly.

Span fidelity is best-effort and never an evaluation gate. A span count that disagrees with receipt `calls` is exporter diagnostics, not grounds to void a trace: the session-record layer — thread messages plus receipts — stays authoritative for accounting and for single-turn troubleshooting, keeps **exported_revision**, and keeps the startup and periodic reconciliation resend. Accept the costs that follow from the decision — three runtime dependencies plus a pinned semantic-conventions version, and a hard seam discipline that the five spans must not quietly grow into.

Authority: [server lifecycle spec](../../specs/qa-chain-server-runtime.md); rationale and delivery ledger: [program map](../../plans/qa-chain-generalization.md). ADR 0101 remains in force. Adopted on 2026-10-19. This supersedes only the dependency-free hand-rolled transport and the "no SDK, no package, no lockfile change" clauses of the previous T12 wording; the allowlist discipline, the redaction boundary, the bounded non-blocking queue, the acknowledgement cursor semantics and the two-second shutdown drain all remain in force. No implementation pass is implied.

## Amendment (2026-10-20): two-layer tracing contract

Operator ruling. This amendment supersedes only the exporter default and selection wording recorded before it — a default of no exporter, with **console** or **otlp** as the only alternatives — and adds the two-layer contract below. The five hand-written spans, the attribute allowlist, the bounded queue, the acknowledgement cursor, the two-second shutdown drain and the rule that a failed write never blocks a turn all remain in force unchanged. **Correction (2026-10-21):** the local span sink is new, not an existing mechanism. `fin_trace_span`, the fin-specific `FIN_TRACE_SPAN_DSN` it writes to and its `FIN_TRACE_SPAN_RETENTION_DAYS` window — default 14 days, `0` keeps rows, pruned by an at-most-hourly `DELETE` — arrive with the two-layer delivery in c626417f. The table and its retention are owned by the host trace sink in `src/fin/host/trace_span_store.py`; the DSN is read and required by the exporter configuration in `src/fin/host/receipt_export.py`.

The **session-record layer** is thread messages plus receipts. It is always on, content-complete, and authoritative for single-turn troubleshooting.

The **trace layer** is spans. It carries structure, timing and allowlisted attributes only, never raw text. It is off by default and is enabled only by an explicit configuration item: the standard `OTEL_TRACES_EXPORTER` setting selects **pg**, **console** or **otlp**. **pg** writes spans to the local `fin_trace_span` table in the database named by `FIN_TRACE_SPAN_DSN` and refuses startup without that variable; **otlp** exports them to any OTLP/HTTP backend, and **console** writes them to the process output. Retention is `FIN_TRACE_SPAN_RETENTION_DAYS` (default 14 days; `0` keeps rows). Exporter failure remains bounded and non-blocking, as above.

The two layers are correlated by **thread_id**, **turn_id** and **trace_id**. The session-record layer answers single-turn troubleshooting; the trace layer adds structure and timing for the same turn. Cross-turn aggregation and alerting belong to the middle platform (中台), not to fin.

This amendment records the operator's contract; it is not a verification result.

## Amendment (2026-10-21): the span read door

The developer TaskPanel reads one turn's trace through `GET /api/threads/{thread}/turns/{turn}/spans`. The route always answers 200 and states `trace_state` instead of the earlier boolean `trace_enabled`, because an empty span list alone cannot distinguish "tracing is off" from "tracing is on but unreadable". The four values are:

- **off** — the boot selected no exporter, so no span is written;
- **local** — the boot selected the `pg` sink and the read succeeded, so an empty list means "this turn has no span", unless the segment's rows are a moment behind the status frame; the view reads once more after one second before treating the empty list as final;
- **external** — the boot selected `console` or `otlp`, so tracing is on but its spans leave the process and the local store is not read;
- **unreadable** — the `pg` sink is selected and the store read failed, so nothing is claimed about this turn's spans.

The state is derived from the exporter selection the application boot resolved once; the route does not re-read `OTEL_TRACES_EXPORTER`, so the view and the export worker cannot disagree, and an unknown exporter token stays a configuration error rather than becoming a fifth state. Only **local** reaches the `fin_trace_span` table. The view renders the receipt fallback — turn facts plus the persisted thinking and tool folds, without receipt `stage_metrics` and without the raw `status_reason` token — under one hint per state, and never as an error. This amendment records the contract; it is not a verification result.

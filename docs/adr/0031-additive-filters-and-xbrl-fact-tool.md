# 0031. Generic catalog filters and retained financial fact tools

Date: 2026-08-25
Status: accepted

Amended 2026-10-16 after operator confirmation and fresh architecture review: the catalog supports general documents without financial identity. New rows require a title and document type; company and period are optional. The catalog owns the initial generic filter allowlist `title`, `doc_type`, `company`, `period`; the [retrieval contract](../../specs/qa-chain-corpus-retrieval.md) fixes exact-match normalization, four-entry/256-byte bounds, pre-I/O typed rejection, all-arm scope enforcement, and unsupported-mode failures. Invalid or unknown generic keys fail explicitly; valid conflicting predicates may return zero hits. Physical financial metadata and the existing financial read projection remain supported.

Replace the dedicated retrieve arguments `cik`, `form`, `ticker`, `filing_date` through upstream expand → fin migrate/expand → fin contract, with actual capability/build and caller-inventory gates. Legacy arguments keep their existing semantics during the compatibility window and intersect generic filters; only migrated supported callers permit removal. Financial fields are optional data, never a prerequisite for ordinary questions. Preserve `get_xbrl_fact`, specialized SQL/fact controls, numeric citation checks and positive financial acceptance. Facts supply numbers; embeddings may resolve aliases but cannot author values. Ranking remains upstream behind the retrieve port (ADR 0030/0061).

Historical decision (2026-08-25): EDGAR-shaped catalog identity was mandatory, financial filters were additive dedicated arguments, and unknown/conflicting filters returned empty hits. The 2026-10-16 amendment supersedes those mandatory-identity, dedicated-argument and unknown-filter clauses; it retains optional financial metadata and specialized fact behavior. The trade-off is explicit caller migration and upstream scope enforcement in exchange for truthful general-document retrieval. Considered alternatives were requiring ticker as company identity and retaining a finance-only catalog. This is an adopted design, not evidence of deployment or runtime acceptance.

# 0041. Degraded signal and partial-failure semantics: `degraded` is set by capability failure, never by empty results

Date: 2026-08-31
Status: accepted

检索响应的降级信号字段名逐字为 `degraded`（布尔，缺省即未降级）与 `degraded_reasons`（有限枚举列表，每项指明是哪一个能力项、属于「未尝试」还是「尝试失败」），两侧不得另立名称、另作翻译或改用等价表述。`degraded` 的置位规则以本 ADR（对应基线 B3）为**唯一权威定义**：规则 1——默认启用的能力因凭证或地址缺失而**无法尝试** → 置位；规则 2——已尝试的能力调用失败 → 置位；规则 3——能力已尝试但未找到任何命中 → **不**置位；规则 4——调用方显式关闭的能力 → **不**置位。部分失败语义（对应 B2）与之配套：一臂成功即放行，仅当存在失败或无法尝试的臂时才置标记；全部臂失败（含向量臂失败且主路径无命中）返回具名失败，不以空结果冒充「命中为空」；无效输入与合法空结果必须区分，两者都不置 `degraded`。

由此显式改判两处既有语义：其一，「图地址缺失即静默跳过且不置降级」改判为**置位**——图地址缺失属规则 1 的「因地址缺失无法尝试」，与向量凭证缺失同性质；其二，「重排失败 fail-open 不标记」改判为**置位**——重排已尝试但调用失败属规则 2，fail-open 只是失败的处置方式，不豁免标记义务。同时明确：凭证缺失**不得**用确定性伪向量兜底，伪向量属于被禁止的静默形态。禁止的静默形态（对应 B3）完整收录为：不得用确定性伪向量、空结果、静默跳过、无标记的顺序回退代替降级信号；任何失败路径必须留下可断言的痕迹——信封标记、具名错误码、可列举的失败记录，三者必居其一。消费规则：调用方必须读取该标记，为真时不得把该次结果当作完整结果使用，须按部分失败语义处置、向用户侧暴露可见信号并记录原因；把降级当空结果处理或忽略该标记是契约违反。理由是：降级信号的全部价值在于把「能力失败」与「合法空结果」区分开——不置位规则（静默跳过、fail-open）在实现上省事，但会让调用方把残缺结果当完整结果引用，直接动摇引用门与答案可信度；四条规则把「未尝试」「尝试失败」「未命中」「显式关闭」四种情况分开，正是为了不把用户可见的失败转嫁成不可见的数据缺失。

Considered Options: 仅记日志不进信封（日志不可被调用方断言，等价于静默）；用错误码替代布尔标记（调用方须解析错误码才能判断完整性，部分成功场景无码可挂）；维持「图地址缺失静默跳过 / 重排 fail-open 不标记」的既有语义（两处失败路径均不可断言，与禁止的静默形态直接冲突，故改判）。

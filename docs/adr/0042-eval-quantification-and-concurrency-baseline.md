# 0042. Eval quantification and concurrency baseline: the B1 numbers are final contract values, not suggestions

Date: 2026-08-31
Status: accepted

评测的量化口径与并发基线采用基线 B1 表的定稿值，为**契约**而非建议值。指标集为 P@5、R@5、Recall@20、nDCG@10、MRR、引用门通过率（由 fin 侧产出）、图臂命中率、错误率、延迟 p50 / p95 / p99——每个配置全部输出，缺任一项该配置即不通过；引用门通过率由 fin 侧在同一份运行结果上产出，两侧报告合并后指标集完整。并发基线分两层：并发 L1（检索 / 读取路径，不含 LLM）为并发 16、持续 120 秒、读写比 9:1、总请求数 ≥ 1200，判定错误数 = 0、5xx < 1%、p50 / p95 / p99 全部落盘；并发 L2（完整 run，含 LLM）为并发 8、持续 120 秒，判定错误数 = 0、p50 < 60 s、p95 ≤ 120 s。延迟阈值 p95 ≤ 800 ms、p99 ≤ 2000 ms（预热请求不计入）**仅作用于并发 L1**，L2 用其自身的 p50 / p95 判据。并发幂等场景（全写）为并发 16、持续 120 秒，判定错误数 = 0、压测前后块总数增量 = 0。消融矩阵为 10 个配置（全开 1 + 逐项关闭 8 + 全关 1），跑 20–40 题的脚本化子集，每配置重复 ≥ 3 次，落原始值与中位数；可独立开关的能力项恰为 8 个。数据集规模：源文档 ≥ 140 篇（≥ 7 种格式 × 每格式 ≥ 20 篇）、切分后块 ≥ 20000 且 ≤ 120000、查询 ≥ 100，全部为真实样本；查询分档为 CI 契约集 40 题（脚本化、无 LLM 判定，每次提交跑）与全量集 ≥ 100 题（四类各 ≥ 10%，每周一次）。评测资源预算：消融 30 次合计约 3–8 小时、夜间窗口串行，全量 100 题每周一次约 1–2 小时，两个并发场景合计 ≤ 30 分钟（含预热）；压测机与服务分离、语料全本地。理由是：并发原为「并发 50、总请求 ≥ 3000」的建议值，未区分 LLM 路径与纯检索路径——L2 受 LLM 延迟支配，与 L1 共用 p95 ≤ 800 ms 的判据会误报；拆成两层并各自给定判据后，阈值才可断言。数据集块数由 ≥ 5000 上调为 ≥ 20000 且 ≤ 120000，是为了让召回与性能数字在真实规模上成立。全部取值经操作者确认定稿并写回两份 spec 的 B1 表，此后两侧正文引用这些数字必须逐字一致，不得另立口径（见 ADR 0040）。

Considered Options: 维持「待确认建议值」标注（数字不可断言，验收无从谈起）；L1 / L2 共用同一套延迟判据（LLM 路径 p95 必然超标，阈值失真）；消融跑全量集（30 次全量不可承受，资源预算行已排除）。

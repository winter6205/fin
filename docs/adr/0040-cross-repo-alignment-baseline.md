# 0040. Cross-repo alignment baseline: a shared, verbatim-locked chapter across the two specs

Date: 2026-08-31
Status: accepted

fin 侧 `specs/corpus-retrieval.md` 与检索服务侧 `specs/retrieval-stack.md` 共享一个同名章节「跨仓对齐基线」，作为两仓之间统一数字口径（并发 / 延迟 / 数据集规模 / 指标集 / 消融矩阵 / 幂等基准 / 评测资源预算）、跨仓契约字段（`source_ref`、幂等键、内容失效、不二次切分、降级信号、部分失败语义、后台路径失败契约）与统一术语的唯一权威。该章节是**契约**而非实现说明：任一侧要改本章，必须双侧在同一次改动中同步修改，不允许单侧先行；验收方式是逐字比对——自 `## 跨仓对齐基线` 标题行之后起、到下一个 `## ` 标题行之前止，去掉首尾空行后取段，对两侧该段分别计算 sha256，两值相等即通过、不等即失败（对应 B6）。凡本章已定之事，两侧正文不得再以假设、开放问题或实现者余地的形式重新提出，也不得写出与之矛盾的数字或语义；正文如需引用数字，一律指向本章，不得另立第二套口径。理由是：两仓各自演化时，数字口径与契约字段最容易各自漂移——口头约定与注释不可断言，只有「同一章节、逐字相同、哈希可比对」才能把跨仓契约变成一条可执行的验收标准；而「唯一权威 + 禁止另立口径」确保漂移在写入时就被拦下，而不是在联调时才发现。

Considered Options: 两份 spec 各写各的数字口径、靠评审对齐（无机器可断言的验收，漂移靠人眼）；只用一份 spec、另一份引用（两仓各自持有 spec 是既有事实，跨仓单向引用会造成所有权不清）；共享章节但不做逐字比对（「大体一致」不可判定，等于没有验收）。

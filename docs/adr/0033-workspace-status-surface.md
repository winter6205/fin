# 0033. Workspace status surface: boot-scoped fields read off the in-process retrieve port

Date: 2026-08-26
Status: accepted

The workspace gets one small status surface (`GET /api/status`, rendered as a Sidebar strip — `plans/workspace-stream-fidelity.md` T9 gating T10). The surface is **boot-scoped configuration plus dependency reachability, never per-run or per-turn telemetry**. IN: **retrieve_reachability** — a typed field value (reachable vs unreachable) standing for whether the in-process retrieve port would answer with its typed `retrieve_unavailable` EXIT (`RetrieveUnavailableError`); an unreachable retrieve is payload data with readable degraded copy, never an HTTP 500, never an empty body or blank strip. IN: **retrieve_adapter_kind** — the resolved adapter behind the port (`mcp` | `fake`, the `FIN_RETRIEVE_ADAPTER` resolution), so a healthy fake boot is distinguishable from a healthy product boot. IN: **model_identity** — the resolved `FIN_MODEL` slug only; never `FIN_BASE_URL`, never key or token material. IN: **corpus_filing_count** — the filing count from the same in-process catalog (`list_filings`) that serves `GET /api/corpus`; zero is a valid rendered value, not an error. OUT: **step_budget_live**, **token_usage_absolute**, and **soft_track_confidence** — run-/turn-scoped values that belong to the SSE stream's contract if they are ever surfaced at all, not to this route. OUT by plan exclusion: any "% of context window" figure; any skill list; the iknow-memory retrieve envelope mismatch stays flagged in that repo (ADR 0032 — no lockstep). Read seam: the route reads the compiled graph's in-process retrieve port plus fin-local config and catalog only — it does not construct its own MCP client, does not add a health-check RPC, and makes no cross-repo call ("MCP client to iknow-memory" stays out of `specs/workspace.md` scope; the port's product adapter already owns that transport per ADR 0032). Open to T10: response-key spelling, whether reachability is probed per request or cached from the last port call, poll vs on-open fetch, and Sidebar copy.

Amended 2026-08-26 (T10 landed, `winter/fidelity-integrate-8400`): the reachability derivation resolved to neither of the two options this record left open. `probe_retrieve_reachability` does not call the port and does not cache a previous call — it predicts the EXIT from configuration, reporting unreachable exactly when the `mcp` adapter is configured and `DEFAULT_MCP_COMMAND[0]` is absent from `PATH`, and reporting the `fake` port reachable because it answers every call. That keeps the rejected health-check RPC out and costs no subprocess, at a stated blind spot: an `iknow-memory` binary that is on `PATH` but does not answer `tools/call` reports reachable. The two-state typed contract, the never-blank strip and the read seam are unchanged — only the derivation sentence above needed correcting, so this record is amended rather than superseded.

Considered Options: HTTP 500 / empty body on unreachable retrieve (breaks the typed two-state route and the never-blank strip); per-run counters on the route (turns a boot surface into run telemetry and duplicates the stream); a dedicated MCP health-check client inside the route (adds the client the spec keeps out of scope); exposing `FIN_BASE_URL` alongside the model id (leaks operator endpoint config for no strip value).
